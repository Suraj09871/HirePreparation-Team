🛢 Database Schema

Core collections used in MongoDB:

Users

_id, name, email, password, role (student/recruiter/admin), createdAt

Jobs

_id, title, company, requiredSkills, description, location, salary, postedBy

Profiles

_id, userId, bio, skills, education, experience, resumeLink

Applications

_id, jobId, applicantId, status, matchScore, appliedAt

⚡ Edge Functions & API Services

POST /api/match

Calculates the skill match score between a student profile and a job listing in real-time.

GET /api/prep-data

Fetches company-specific preparation modules, questions, and roadmaps.

Skill Matching Algorithm

Sunny's Module
Match % = (Σ skill_scores / required_skills.length) × 100
  • ▪ Exact match: 1.0 score (e.g., 'React' = 'React')
  • ▪ Partial match: 0.6 score (e.g., 'React.js' contains 'React')
  • ▪ Alias match: 0.4 score (e.g., 'JS' ↔ 'JavaScript')
  • ▪ Supports 15+ alias groups (TypeScript ↔ TS, Python ↔ Py, etc.)

Hiring Probability Formula

Sunny's Module
Score = (Skill Match × 60%) + (Resume Score × 25%) + 15% base
  • ▪ Skill component: match_percentage × 0.6
  • ▪ Resume component: resume_score × 0.25
  • ▪ Base probability: 15% (floor for all candidates)
  • ▪ Capped at 100%

🛡 Auth & Security

  • JWT Authentication: Secure token-based authentication for all protected routes.
  • Role-Based Access Control (RBAC): Strict separation between Student, Recruiter, and Admin endpoints.
  • Password Hashing: Bcrypt implementation for secure password storage.
  • Google OAuth: Integration for fast and secure social login.
